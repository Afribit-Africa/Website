## Security

- Patched Next.js to 16.3.8, React/React DOM to 19.2.8, NextAuth to 4.24.15;
  Prisma client/CLI remain on matching 6.19.3. Updated compatible transitive fixes.
- SMTP uses patched Nodemailer 10.0.13 through the `nodemailer-smtp` package alias.
  NextAuth v4's unused email provider declares an optional Nodemailer 7 peer;
  the alias avoids installing that vulnerable peer or forcing an incompatible tree.
  Nodemailer 10 supplies its own types. Only Google sign-in is enabled.
- Every JWT session read rechecks the current DB role. Deleted/demoted users and
  lookup failures lose privileged access, including admin APIs. Google email must
  be verified. Client session-update data cannot promote a role.
- Public forms enforce known origins, JSON content type, a 32 KiB streamed body
  limit, bounded/trimmed fields, a honeypot and five requests per 15 minutes per IP.
  CAPTCHA is verified server-side when configured; partial configuration fails closed.
- Escaped all dynamic email HTML and neutralized contact-subject line breaks.
  Blank optional subjects now work. Newsletter responses do not disclose membership.
- Security headers remove the framework signature, prevent MIME sniffing and
  cross-origin framing, constrain object/base embedding, and set referrer/permissions
  policies. Vercel adds HSTS without affecting subdomains. This is **not a strict
  script-source CSP**; a nonce-based policy needs a separately tested rollout.
- JSON-LD escapes `<` to prevent script termination by content strings.
- BTCPay invoice creation requires explicit `BTCPAY_CHECKOUT_ENABLED=true` in both
  API and SDK. Existing invoices remain readable and webhooks remain usable.
- Signed webhooks validate the configured store, ID and authoritative amount/currency.
  Official `sha256=` HMAC headers use timing-safe comparison. Only full invoice
  settlement can credit; completion and USD program increments transact together.
  Polling is read-only, retries cannot double-credit, and BTC/USD totals remain separate.
  Notification delivery is best-effort, not a durable email outbox.

### Remaining Configuration / Dependency Work

The saved Upstash Redis hostname returns `ENOTFOUND`. Distributed limits are therefore
**opt-in**, not activated just because old credentials exist. CAPTCHA and per-instance
limits remain active. Reconnect the Afribit Vercel Redis integration, verify `PING`,
then set `PUBLIC_FORM_REDIS_ENABLED=true` with both REST credentials and redeploy.
Once enabled, Redis failures fail closed. Without it, limits are not global across
serverless instances. Outside Vercel, forwarded IP headers need a trusted proxy.

`npm audit` and `npm audit --omit=dev` report **three high advisories in one chain**:
`deepmerge-ts` -> `@prisma/config` -> `prisma`. No critical advisories remain.
The affected merge runs in CLI configuration; this app does not feed request payloads
to it. Do not use `npm audit fix --force`: npm proposes a breaking Prisma downgrade.
Plan a compatible patched CLI upgrade; do not silently override a major merge API.
No claim of zero vulnerabilities or a comprehensive penetration test is made.
